# Fleet Console — правила для сессий Claude

Личный локальный веб-сервис поверх fleet. Источник правды по архитектуре и требованиям —
`docs/ARCHITECTURE.md`; читать его первым. Нашёл в документе ошибку или расхождение с реальным
кодом fleet — скажи и предложи правку документа, не обходи молча. Работа идёт по фазам из раздела
«Фазы и критерии готовности»; фаза считается закрытой только после проверки её гейта.

## Fleet — чужой репозиторий

- Путь: `/Users/afsautin/repos/fleet`. Читать можно сколько угодно.
- Ничего в нём не менять, не коммитить, не переключать ветки, не запускать там `uv sync`
  (`uv run` без `--no-sync` тоже синхронизирует `.venv`). Для пробного запуска CLI брать
  `.venv/bin/fleet` как есть; для экспериментов с worktree — копия в scratchpad.
- Сервис работает с fleet только через зеркало `~/.fleet-console/fleet.git` и worktree на SHA.

## Кластер

- Можно без вопросов: чтение (`kubectl get/describe/logs/auth can-i`, `get --raw`), port-forward,
  ssh-сессия к бастиону (`ssh -N fleetbastion`).
- Только после явного «да» пользователя в чате, с показом точной команды: всё, что меняет состояние
  или тратит GPU — `mlsc.create_job`, `start_llm`/`stop_llm`, сабмит, запись лимита агентов,
  остановка или удаление workflows, `kubectl create token`, любой `exec` с побочным эффектом.
- Без ssh-сессии к бастиону `kubectl` не работает: context `internal` смотрит на
  `127.0.0.1:8443`, который открывает `LocalForward` из `~/.ssh/config`. Та же сессия даёт
  SOCKS `127.0.0.1:1080`; через него доступны `pypi-mirror.gitverse.ru` (для `uv sync` worktree:
  `HTTPS_PROXY=socks5h://127.0.0.1:1080`) и ingress-хосты `*.sberai-rnd.ru`.
- Поднятые для проверки туннели и пробросы гасить в конце и говорить об этом.

## Качество

- Логика покрыта тестами, которые не требуют кластера, fleet и `kubectl`: всё внешнее —
  заглушками (подпроцессы, git, kubectl, файловая система через tmp_path).
- UI проверяется самостоятельно: запустить приложение, пройти все экраны во встроенном
  браузере, снять скриншоты в светлой и тёмной теме и в узком окне, исправить всё, что выглядит
  перегруженным.
- Принципы UI: минимум экранов; одно главное действие на экране; детали по раскрытию
  (форма → «Дополнительно» → полный конфиг); статус кластера и прогонов всегда в шапке;
  никакой декоративности.
- Коммиты небольшими шагами с понятными сообщениями; одна ветка на фазу (`phase-N`).
- В конце работы: что сделано, что и как проверено, что не проверено, какие вопросы остались.

## Код

- Python 3.12, uv, NiceGUI; запуск `uv run fleet-console`. Зависимости сервиса — с PyPI
  (зеркало gitverse сервису не нужно).
- Структура и имена модулей — по разделу «Стек и структура репозитория» документа.
- Fleet вызывать как `uv run --project <worktree> --no-sync fleet …` с cwd = worktree.
- Секреты только через окружение подпроцесса; в логи и `resolved.yaml` не попадают.

## Грабли, найденные на Ф0

- NiceGUI: `@ui.refreshable` на уровне модуля копит контейнеры всех клиентов (в том числе удалённых)
  и падает на `refresh()`; объявлять refreshable только внутри функции страницы.
- UI-тесты: `pytest_plugins = ["nicegui.testing.user_plugin"]`, маркер
  `nicegui_main_file("tests/ui_main.py")`, фейковый контекст в `tests/fakes.py`. В симуляции
  `ui.run` возвращается сразу. `caption` у expansion не считается текстом для `should_see`.
- Дочерние команды: `Runner` убирает `VIRTUAL_ENV` (сервис сам живёт в venv uv, иначе дочерний uv
  ругается) и ставит `NO_COLOR`; вывод режется и по `\r`, иначе прогресс git/uv — одна строка.
- Зеркало считается готовым только по маркеру `fleet.git/fleet-console.last_fetch`: `HEAD`
  появляется в самом начале клонирования; без маркера каталог удаляется и клонируется заново.
- `kubectl auth can-i` сразу после подъёма ssh может транзитно ответить ошибкой — права
  перепроверяются, пока есть хоть одно «✗».
- Запуск для проверки: preview `fleet-console` из `.claude/launch.json` (`uv run fleet-console`,
  порт 8080). `reload=False`: после правок кода сервер перезапускать. Скриншоты — в `screenshots/`.
- Старые ветки fleet тянут другой патч Python: `uv sync` докачивает интерпретатор через SOCKS,
  первая подготовка такой ветки — минуты.

## Грабли, найденные на Ф3

- UI-тесты: `should_see` не видит строки `ui.table` — проверять `table.rows`; клик по строке —
  `user.find(kind=ui.table).trigger("rowClick", [None, row])`; `user.find("Запустить").click()` жмёт элемент с
  наименьшим id среди подходящих (на странице это другая кнопка) — метить кнопки `.mark()`.
- Встроенный браузер: окно 800×600, выпадающие списки Quasar уезжают за экран — перед работой с формой
  ставить viewport 1280×1100 и возвращать `desktop` в конце.
- Стадии бенча — отдельные группы процессов (`setsid` через `sh -c '… >> log; echo $? > exit'`); `killpg`
  убивает и обёртку, exit-файла нет — так менеджер отличает «убили» от «упала». Лог пишет сам процесс, поэтому
  секреты вырезаются при показе, а не при записи.
- `--print-config` только с заглушками секретов (`DUMMY_ENV`): `oc.env` резолвится, и настоящий токен попадает
  в `resolved.yaml` (так было в сессиях Ф2, вычищено).
- fleet добавляет к `run_id` суффикс времени, если ни один override не содержит `run_id`; сервис всегда
  передаёт `experiment.run_id=<id каталога>`, иначе стадии не увидят друг друга.
- Файл группы в каталоге прогона (`runs/<id>/harbor/agent/x.yaml`) перекрывает файл ревизии при
  `hydra.searchpath` — проверено на master; так работает «Править в этом прогоне».
- Ключи S3 не просить в `secrets.env`: они лежат в профиле `[gcvmfleet]` `~/.aws/credentials`, сервис читает их
  оттуда и отдаёт fleet как `AWS_*_gcvmfleet` через окружение подпроцесса.
